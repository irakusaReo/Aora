# Base Sepolia and native USDC — what the documentation says

Read on **2026-10-18** unless a section says otherwise. Nothing is from memory. Each section names its page. Re-read the page before changing `services/api/src/modules/chain/`; record the new date here. Base Sepolia is a testnet: nothing here moves real money, and Base mainnet is never configured (CLAUDE.md rules 1 and 10).

## Network (page: docs.base.org `get-started/connect-to-base`)

- Base Sepolia chain ID **84532**; public RPC `https://sepolia.base.org`; explorer `https://sepolia.basescan.org`.
- Observed through the public RPC on 2026-10-18: `eth_chainId` returned 84532; block timestamps over 1,000 blocks averaged **2 seconds** per block.

## Public RPC limits (page: docs.base.org `specifications/node-operators/run-a-node`)

- "Our RPCs are rate-limited, they are not suitable for production apps." No figure is published. AORA's calls are few and bounded (one scan range per job run, a handful of reads per open operation), so the public endpoint serves development and staging. A second, independent provider is on the pre-pilot list (D-11).

## Finality (page: docs.base.org `specifications/transactions/transaction-finality`)

The page describes four stages for ordinary Base transactions (it does not separate mainnet and Sepolia):

| Stage | About | Base's statement on reorganisation |
|---|---|---|
| Flashblock inclusion | 200 ms | under 0.001% |
| L2 block inclusion | 2 s | "near 0%"; one L2 block has ever reorganised |
| L1 batch inclusion | 2 min | "effectively 0%" |
| L1 batch finality | 20 min | "effectively 0%"; "in practice impossible to reverse" |

**AORA's confirmation policy** (`chain.confirmation_policy`, version 1, sandbox data): 60 confirmations (about two minutes, the L1 batch inclusion stage) for ordinary amounts; 600 confirmations (about twenty minutes, L1 batch finality) at or above 1,000 USDC. Changing it is a data change with an effective date.

## Faucets (pages: docs.base.org `get-started/get-funds`; faucet.circle.com; docs.cdp.coinbase.com `faucets/introduction/welcome`)

- Base's "Get Funds" page points to the Base faucets and to Circle's faucet for test USDC ("Select Base Sepolia").
- Circle faucet: 20 USDC every 2 hours per address and chain; "public and permissionless", no account.
- Coinbase Developer Platform faucet: Base Sepolia ETH, 0.0001 ETH per claim, up to 1,000 claims in 24 hours; needs a CDP sign-in (the owner's step).

## Contract verification (page: docs.etherscan.io `supported-chains`)

- Etherscan lists Base Sepolia (84532) as **"Paid Tier Only"**. A paid plan is a billable resource, so no `ETHERSCAN_API_KEY` is requested (phase-5 plan P5-8).
- **Sourcify** is used instead. `forge verify-contract --help` (Foundry 1.8.4) lists `--verifier sourcify` and `blockscout`, neither needing a key. Sourcify's chain list (`https://sourcify.dev/server/chains`, read 2026-10-18) has "Base Sepolia Testnet", chain 84532, `supported: true`. `contracts/scripts/deploy.mjs` verifies there after deployment.
